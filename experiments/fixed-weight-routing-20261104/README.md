# 固定权重路由：源码快照和实验结果（2026-11-04）

目标是相同模型、资源、数据和训练规则下，实际用于优化器更新的完整 GRPO 组/GPU·h 相对原生至少提升 5%。当前目标尚未达到。本目录是不同来源的审阅快照，不是可直接部署的完整版本。

同一 35B BF16 模型、两张 A800、每副本 TP1 的固定权重实验中，先比较保留原生缓存的 cache-aware 默认/调参及会话亲和，选择校准中最快的调参基线。独立确认三对完整组吞吐变化为 **+13.34%、+12.63%、−10.99%**。每臂 6 个组件完整组、192 次成员/轮次的输入、采样、输出 Token 和报告概率逐项一致。

合并确认吞吐为 **+4.32%**；计入该窗口的启动、校准和清理并按预定规则分摊后为 **+0.619%**，未达 5% 筛选目标。该窗口约 0.472 GPU·h，实际优化器更新 0；不能将组件结果称为 RL 训练收益。更早失败、保留和训练成本不包含在该窗口数字中。

六次确认缓存命中总量均为 131072 Token。96 次项目决策中 11 次施加目标、85 次回退；六个长样本首轮全部回退。尚无准确的调度器等待和原生回退目标，不能认定耗时变化来自额外 KV 复用。结构化数值见 [results.json](results.json)。

8K 检查点专项中，候选只复用完整对齐的预填充末尾 FP32 状态，冷热 Token 及报告概率在该条件下相同；基线复用更长解码检查点时概率存在差异。这不证明中间 BF16 状态、16K 或更长上下文已修复。另一次旧训练单对各完成 12 次更新、96 组，项目相对原生的完整组/GPU·h 观察区间约 −2.53% 至 −1.84%；区间来自占卡起点不确定性，并非置信区间或因果结论。

## 代码来源与边界

- [driver/](driver/) 保存执行过的固定权重实验驱动、影子建议和目录客户端；真实目标头仅由独立组件驱动发送，生产建议器仍为影子模式。机器资源、模型、二进制、训练端与源服务需要自行配置，快照不是完整部署包。
- [预填充补丁](patches/prefill-checkpoint.patch)是 SGLang 冻结版本局部候选；[目录补丁](patches/native-directory.patch)和 [stable-target 补丁](patches/stable-target/)分别属于推理引擎、Gateway 与 VeRL 的不同版本，不能作为单一补丁集直接应用。
- [源 GPU 释放候选](patches/source-release-overlap.patch)的 CPU 并发/失败检查已完成；GPU 物理资源交还、Actor 重叠和端到端收益尚未验证。
- 真实参数发布、混合缓存身份和 16K 一致性仍需验收；`fixed_weights` 防护和原参数发布权威保持。
- `SOURCE_MANIFEST.json` 标注文件来源和 SHA；原始请求、输出、内部地址和机器标识未公开。

## CPU 检查

在 `driver/` 执行 `python3 -m unittest test_screen test_readiness test_bounded_routing -v`。原 Linux CPU 验证完成 14 项检查，并用真实 Linux Gateway + CPU 夹具执行正常/慢管理接口两轮完整工作流，共 480 次成员/轮次；这不是 GPU 性能结果。整理公开副本时，macOS 首次与完整性扫描并行运行时，一项 100ms 路由测试返回 fallback；随后单项和完整 14 项串行重跑通过。具体触发原因未确认，时间敏感性及首次失败保留，不宣称首次运行无失败。
